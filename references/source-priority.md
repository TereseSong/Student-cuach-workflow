# 外部信息源优先级

当本地知识库未覆盖，或用户明确要求先查指定来源时，按这份顺序补检索。

## 当前已接入的优先来源

### 1. 公众号接口检索

- 接口：`https://www.dajiala.com/fbmain/monitor/v3/kw_search`
- 适用场景：
  - 本地知识库没覆盖
  - 用户明确指定公众号来源
  - 需要先按公众号关键词、作者、号名检索

默认策略：

1. 先查本地 `knowledge-base/`
2. 本地没有，先查 `公众号接口检索`
3. 接口结果不够，再补 `搜狗微信搜索`
4. 高频命中结果整理后放进 `knowledge-base/01-项目知识库/`

推荐实现：

- 直接用 `scripts/wechat_source_search.mjs`
- API key 用 `DAJIALA_WECHAT_KEY` 或命令行 `--key`

回答标记：

`<外部参考>公众号接口检索 / 关键词</外部参考>`

### 2. 公众号 / 搜狗微信搜索

- 来源入口：`https://weixin.sogou.com/`
- 适用场景：
  - 用户明确说“先查公众号怎么写”
  - 用户给了公众号文章、公众号作者、公众号关键词
  - 项目知识主要沉淀在公众号文章里

默认策略：

1. 先查本地 `knowledge-base/`
2. 本地没有，先查 `公众号接口检索`
3. 接口结果不够，再优先查 `搜狗微信搜索`
4. 命中公众号文章后，再抓取文章正文
5. 抓回来的文章如果后续要反复用，整理后放进 `knowledge-base/01-项目知识库/`

## 推荐实现方案

当前环境里，没有现成 MCP 能直接搜公众号。

优先可用方案：

1. `scripts/wechat_source_search.mjs`
   - 直接调用公众号接口检索
   - 适合先拿关键词结果
   - 可以把结果保存进本地知识库
2. `baoyu-url-to-markdown`
   - 适合抓公开网页
   - 可以抓搜狗微信搜索结果页，也可以抓具体公众号文章页
   - 抓回来后转成 markdown，适合进入本地知识库
3. 内置 web 搜索
   - 适合临时验证、补充检索
   - 搜索时优先限制到 `weixin.sogou.com`
4. 后续自建 skill 或脚本
   - 如果后面公众号会成为高频来源，建议单独做一个“公众号搜索 -> 文章抓取 -> 入库”的小 skill

## 使用约定

- 用户点名公众号来源时，不要先去泛搜全网
- 先查 `公众号接口检索`，再看是否需要补 `weixin.sogou.com`
- 如果接口只给到摘要或列表，不要直接拿摘要当全文结论
- 如果搜狗结果页只给到摘要，不要直接拿摘要下结论，尽量继续抓文章正文
- 如果正文抓不到，要明确说“只命中搜索摘要，没拿到全文”

## 回答时怎么标记

命中公众号接口时，统一标记为：

`<外部参考>公众号接口检索 / 关键词</外部参考>`

如果进一步用了搜狗微信搜索，再标记为：

`<外部参考>搜狗微信搜索 / 关键词</外部参考>`

如果已经拿到具体文章正文，统一标记为：

`<外部参考>公众号文章 / 标题或作者</外部参考>`

# Router

先判断任务属于哪一种模式，再加载最小引用集。

## 模式 1：学员行动日志点评

触发信号：

- 用户提到“学员行动日志”“点评”“教练反馈”“复盘点评”
- 输入中包含一段日志、日记、当日动作记录

执行：

1. 提取 `【待解答】`、`【待延伸】`、`【待确认】`
2. 检索本地知识
3. 生成带 `<知识库参考>` 的点评
4. 用 `review-checklist.md` 做一次质检

读取：

- `knowledge-base-search.md`
- `coaching-template.md`
- `review-checklist.md`

## 模式 2：学员问题解答

触发信号：

- 用户只给问题，没有完整行动日志
- 用户要求“帮我回答学员这个问题”
- 用户要求“结合知识库和联网信息回答”

执行：

1. 提炼核心问题
2. 先检索项目知识
3. 本地不足时，再补外部权威资料
4. 先回答问题，再补一条动作建议或风险提醒

读取：

- `knowledge-base-search.md`
- `coaching-template.md`

## 模式 3：项目知识检索

触发信号：

- 用户要求“先检索知识库”“查项目资料”“找课程里怎么说”
- 用户要做知识问答、知识提炼、证据收集
- 用户要“先整理结论，再决定怎么回学员”

执行：

1. 明确检索目标
2. 输出命中文件、命中主题、关键结论、未覆盖点
3. 只有用户继续要求时再进入点评或答疑

读取：

- `knowledge-base-search.md`

## 模式 4：技能维护

触发信号：

- 用户要求“优化这个 skill”“补结构”“改 prompt”“增强检索”

执行：

1. 先审阅 `SKILL.md` 和已有 `references/`
2. 补路由、契约、检索规则和模板
3. 保持 SKILL.md 只做导航，把细节下放到引用文件

读取：

- `SKILL.md`
- 当前被改动的引用文件

## 模式 5：学员日志模板优化

触发信号：

- 用户要求“优化日志模板”“让学员更好提交日志”“规范行动日志”
- 用户说“点评总是信息不够”“日志写得太虚”

执行：

1. 先看当前日志模板或现有样本
2. 用 `student-log-template.md` 补齐关键字段
3. 如有必要，再用 `review-checklist.md` 反推日志缺口

读取：

- `student-log-template.md`
- `review-checklist.md`

## 模式 6：知识入库整理

触发信号：

- 用户要求“整理知识库”“把资料放进 knowledge-base”“优化入库规范”
- 用户开始上传课程资料、群聊答疑、外部摘录、官方文档整理、案例拆解

执行：

1. 判断资料更适合放入哪个知识库目录
2. 用 `knowledge-ingestion.md` 统一成可检索格式
3. 必要时补来源、日期、适用场景

读取：

- `knowledge-ingestion.md`

## 模式 7：共识问题提炼

触发信号：

- 用户要求“提炼共识问题”“总结大家的共同问题”“给圈友发统一建议”
- 已经连续点评了多条学员日志，用户希望做群发提醒或阶段复盘
- 点评结束后，用户确认要把最近日志里的重复问题抽成共识

执行：

1. 回看最近已点评日志或已沉淀案例
2. 提取重复出现的卡点、误区、动作缺口、风险点
3. 输出“共识问题 + 统一建议”版本
4. 完成去 AI 味复检
5. 将最终版本写入 `knowledge-base/02-答疑案例/`

读取：

- `knowledge-base-search.md`
- `coaching-template.md`
- `review-checklist.md`
- `coach-voice.md`
- `self-evolution.md`
- `consensus-extraction.md`

# 本地知识检索

在任何点评、答疑或建议输出前，先完成本地检索。本地未覆盖时，再按固定顺序补外部检索。

## 检索顺序

1. 先查用户当前消息明确点名的文件、目录、知识库
2. 再查当前 skill 下的 `knowledge-base/`
3. 再查项目里明显属于知识资料的文件：
   - 文件名包含 `知识库`、`课程`、`训练营`、`航海`、`作业`、`答疑`、`复盘`、`案例`、`脚本`、`编码`、`开发`、`SOP`
   - 扩展名优先 `md`、`txt`、导出的笔记类文本
4. 如果仍不够，再用日志关键词扫项目其他文件
5. 如果本地仍不够，再按下面顺序做外部补检索：
   - 用户点名的站点、链接、官方仓库、官方文档
   - 用户点名的信息源白名单，例如 `搜狗微信搜索 / 公众号`
   - 已接入的信息源接口，例如 `公众号接口检索`
   - 产品官方文档、API 文档、规则页、发布说明
   - 高质量社区讨论、案例文章、行业资料

## 检索方法

推荐顺序：

1. 先按文件名找
2. 再按标题、章节名、固定术语找
3. 最后按学员日志中的高频动作词和问题词找

优先使用 `rg` 或等价快速检索工具。只打开命中的关键片段，不整篇读取大文件。

如果在 `knowledge-base/01-项目知识库/` 找到明确 SOP 或规则，默认优先于项目内其他松散资料。

如果用户明确指定某个外部信息源，例如公众号、搜狗微信搜索，不要先泛搜全网，先按指定来源检索。

如果本地知识库没有命中，且主题适合公众号来源，默认顺序是：

1. 公众号接口检索
2. 搜狗微信搜索
3. 公众号文章正文抓取

## 关键词展开

从用户输入或学员日志中，至少展开三类词再检索：

- 问题词：如 `为什么卡住`、`接口报错`、`选题没反馈`、`转化低`
- 动作词：如 `发内容`、`改脚本`、`写代码`、`调试`、`复盘数据`
- 风险词：如 `违规`、`误判`、`过度承诺`、`只看播放`、`只会复制不理解`

如日志中的词过于口语，先改写成更稳定的检索词再搜。

训练营/航海/知识付费场景里，建议顺手展开：

- 角色词：`学员`、`教练`、`作业`、`日志`
- 节奏词：`日更`、`发布频率`、`复盘`、`下一步`、`里程碑`
- 结果词：`转化`、`询单`、`进粉`、`提交率`、`完成率`

如果是 AI 编程、技术训练营等主题，建议额外展开：

- 技术词：`安装`、`环境变量`、`依赖`、`报错`、`调试`、`部署`
- 能力词：`需求拆解`、`最小可用`、`重构`、`测试`、`文档`
- 工具词：产品名、框架名、模型名、API 名、命令名

## 匹配规则

- `【待解答】` 优先匹配定义、策略、SOP、判断标准、常见问题
- `【待延伸】` 优先匹配执行顺序、频率、节奏、复盘指标、拆解动作
- `【待确认】` 优先匹配风险提醒、反例、禁忌、常见误判、纠偏建议

## 检索结果转写规则

检索命中后，不要直接把资料原话或“资料出处感”搬进点评正文。

默认先做这一步转换：

1. 先用检索命中的内容形成一句教练判断
2. 再补一句“为什么我现在这么建议”
3. 最后才决定要不要在正文后单独补参考

优先写成：

- `按你这组数据，我会先……`
- `你现在更像是卡在……`
- `这个阶段我一般会先盯……`
- `这步我会先收一收，不然……`

不要直接写成：

- `项目手册里说……`
- `课程里讲过……`
- `某位老师分享过……`
- `根据知识库……`

如果是给教练内部挑选草稿，允许保留 `<知识库参考>`，但默认也放在正文之后单独一行，不把资料来源嵌进判断句。

## 项目知识检索输出

当任务只是“检索项目知识”时，输出至少包含：

1. 命中的文件或主题
2. 每个命中的关键结论
3. 能直接执行的规则或动作
4. 没检索到的空白点
5. 是否进入了外部补检索，以及补到了什么

## 引用规则

引用必须使用真实稳定定位，优先级如下：

1. 章/节编号
2. Markdown 标题路径
3. 文件名 + 最近主题

引用格式统一为：

`<知识库参考>真实文件名 / 真实标题或主题</知识库参考>`

输出时，引用标签必须独立分行，不能和正文写在同一段或同一句里。

如果任务是“学员日志点评”或“学员问题解答”，引用的作用是给教练回看依据，不是替正文说话。正文优先像教练自己的经验判断，引用只做后置支撑。

不得编造章节号、标题名或定位文字。

如果用了外部来源，统一写为：

`<外部参考>来源名 / 主题关键词</外部参考>`

`<外部参考>` 也必须独立分行输出。

如果命中搜狗微信搜索或公众号文章，优先写成：

- `<外部参考>公众号接口检索 / 关键词</外部参考>`
- `<外部参考>搜狗微信搜索 / 关键词</外部参考>`
- `<外部参考>公众号文章 / 标题或作者</外部参考>`

## 冲突处理

- 学员做法与知识库冲突时，明确写：
  `这一步和知识库建议不一致，建议改为……`
- 两份资料冲突时，优先：
  1. 用户点名资料
  2. `knowledge-base/01-项目知识库/` 中更新的操作型资料
  3. 细节更具体、执行性更强的资料
  4. 外部来源中更贴近当前项目主题的资料

## 未覆盖处理

如果本地资料没有命中，先明确写：

`本地知识库未覆盖该问题，已进入外部补检索。`

外部补检索后仍没有稳定结论，再写：

`知识库中未覆盖该问题，建议参考行业通用做法：...`

这类建议默认视为低置信度，不要伪装成知识库结论。
